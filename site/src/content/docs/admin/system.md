Уведомление приходит **только когда новый образ уже собран CI** (проверка по GitHub Actions), поэтому «Обновить» гарантированно скачает свежий образ и бот перезапустится. Уведомление самоудаляется через 60 секунд. Точное сравнение версий работает с образов, собранных с вшитым commit SHA (через CI).

## ✉️ Почта кабинета

Раздел **Система → ✉️ Почта**. Нужен веб-кабинету: без него кабинет работает как
раньше — регистрация без подтверждения адреса и без восстановления пароля.

Что появляется, когда почта включена:

- **подтверждение адреса** при регистрации. Пока адрес не подтверждён, аккаунту
  закрыты покупка, пополнение, промокод и доступ к тарифам «по списку» — почта
  участвует в списках допущенных, и неподтверждённый адрес по сути чужой. Вход,
  просмотр подписки и ссылка на неё остаются доступными;
- **восстановление забытого пароля** по ссылке из письма (ссылка живёт час);
- **уведомление о смене пароля** на сам адрес.

Аккаунты, заведённые до появления этого раздела, считаются подтверждёнными:
апдейт не отрезает действующих покупателей от оплаты.

### Два способа отправки

- **SMTP** — свой сервер или любой релей (Yandex, Mail.ru, SendGrid, Mailgun —
  у всех он есть). Адрес сервера вводится строкой `smtp.example.com:587`, порт
  можно не указывать: он подставится по выбранному шифрованию (587 для STARTTLS,
  465 для TLS). Вход по паролю без шифрования запрещён.
- **Внешний API** — HTTPS-шлюз. Нужен там, где хостер закрыл исходящие
  почтовые порты и остался только HTTPS. Адрес шлюза настраивается; по умолчанию
  используется приёмник вида `https://api.resend.com/emails` (тело запроса —
  `from` / `to` / `subject` / `text` / `html`).

Кнопка **📨 Отправить тестовое** шлёт письмо на адрес отправителя и показывает
ошибку сервера целиком — по ней и видно, что не так с портом, паролем или
подтверждением домена.

Для ссылок в письмах обязателен **публичный адрес** бота (раздел «Вебхуки»): без
него письмо отправлять некуда вести, и бот откажется его слать.

Письма служебные и редкие: не чаще одного в минуту и не больше пяти в сутки на
аккаунт, чтобы форму нельзя было превратить в рассылку с вашего сервера.

## 🔗 Привязка Telegram к аккаунту кабинета

На экране **«Аккаунт»** в кабинете у аккаунта, заведённого по почте, есть кнопка
входа Telegram. После привязки:

- в кабинет можно входить и кнопкой Telegram, и прежними почтой с паролем;
- бот в чате показывает ту же самую подписку, баланс и историю;
- **ссылка подписки не меняется** — у учётки в панели проставляется `telegramId`,
  само имя учётки остаётся прежним (панель не умеет переименование, а переезд
  имени означал бы новую ссылку и переподключение приложения).

Привязка возможна, **только если у этого Telegram ещё нет аккаунта в боте**.
Пустая строка от одного нажатия «Старт» помехой не считается — переносить с неё
нечего. Если аккаунт есть (подписка, платежи, баланс), бот откажет: слить две
истории покупок автоматически нельзя, не решая за человека судьбу оплаченного —
такие случаи разбираются вручную через поддержку.

В закрытом боте (по приглашениям или вайтлист) привязка к Telegram, которого бот
не пускает, тоже отклоняется — иначе человек остался бы снаружи вместе со своей
оплаченной подпиской.
