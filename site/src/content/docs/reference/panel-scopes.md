На панели Remnawave **3.x** у API-токена есть скоупы: токен может всё, что в них перечислено, и ничего больше. Если боту не хватает права, панель отвечает `403 Forbidden`, и функция молча не работает.

На панели **2.x** скоупов нет — там токен и так может всё, страница вам не нужна. При обновлении панели до 3.x старые токены мигрируют сами.

## Готовый список

Полный набор для бота со всеми функциями:

```
system:remnawave-health
system:stats
users:list
users:stream
users:by-id
users:by-username
users:create
users:update
users:delete
users:reset-traffic
users:revoke-subscription
internal-squads:list
external-squads:list
hosts:list
hwid-user-devices:list-by-user
hwid-user-devices:delete-all
node-plugins:list
node-plugins:update
node-plugins:executor
subscription-page-configs:list
subscriptions:subpage-config
```

Ниже — то же самое по частям: что обязательно, а что нужно только под конкретную функцию.

## Обязательный минимум

Без этих прав бот не работает вообще: не пройдёт проверка связи, не найдёт пользователя, не выдаст и не продлит подписку.

| Скоуп | Зачем боту |
|---|---|
| `system:remnawave-health` | проверка связи с панелью — мастер настройки и экран «Подключение к панели» дёргают её **первой**, до всего остального |
| `system:stats` | число пользователей панели на экране «Система» и в мастере |
| `users:stream` | поиск аккаунта по Telegram ID — основной способ на панели 3.x |
| `users:by-username` | запасной поиск для аккаунтов без Telegram ID (созданных ботом по имени) |
| `users:by-id` | привязка существующего аккаунта панели к человеку в админке |
| `users:list` | постраничные обходы панели: переезд с другого бота, разовые сверки, backfill доп-подписки |
| `users:create` | выдача подписки новому покупателю и триал |
| `users:update` | продление, лимиты, сквады, блокировка и разблокировка, привязка Telegram ID |
| `users:delete` | удаление аккаунта из админки и снятие доп-подписки |
| `users:reset-traffic` | обнуление трафика при возврате триала и в действиях админа |
| `users:revoke-subscription` | перевыпуск ссылки подписки |
| `internal-squads:list` | выбор внутренних сквадов в мастере, тарифах и триале |
| `external-squads:list` | то же для внешнего сквада |

## По функциям

Эти права нужны, только если функция включена. Без них остальное продолжает работать.

| Функция | Скоупы | Что сломается без них |
|---|---|---|
| Страны и число конфигов в карточке тарифа | `hosts:list` | строка со странами пропадёт, цена и выдача не пострадают |
| Экран «Мои устройства», счётчик и сброс устройств | `hwid-user-devices:list-by-user`, `hwid-user-devices:delete-all` | список устройств пуст, кнопка сброса отвечает ошибкой |
| Торрент-блокер: «Снять блокировку IP» и «В исключения» | `node-plugins:list`, `node-plugins:update`, `node-plugins:executor` | кнопки в уведомлении блокера отвечают `403` |
| Мини-апп «Подключение»: приложения со страницы подписки | `subscription-page-configs:list`, `subscriptions:subpage-config` | бот покажет свой встроенный список приложений вместо настроенного в панели |

## Как панель проверяет права

Скоуп — это `ресурс:действие`. Панель пускает запрос, если в токене есть хотя бы одно из четырёх:

- `*` — все права;
- `ресурс:*` — например, `users:*`;
- `ресурс:read` или `ресурс:write` — все чтения или все записи ресурса;
- точный скоуп эндпоинта — например, `users:stream`.

То есть вместо длинного списка выше можно выдать `users:*`, `system:read`, `internal-squads:list`, `external-squads:list`, `hosts:list`, `hwid-user-devices:*`, `node-plugins:*`, `subscription-page-configs:list`, `subscriptions:subpage-config` — прав станет больше, чем нужно, но бот заработает.

## Если панель отвечает 403

- **403 при сохранении адреса или токена в админке, «панель не на связи».** Чаще всего нет `system:remnawave-health`: проверка связи начинается именно с неё, поэтому токен выглядит нерабочим целиком, хотя остальные права на месте.
- **403 на кнопках торрент-блокера.** Нет `node-plugins:executor` или `node-plugins:update`.
- **Бот «теряет» подписку и заводит второй аккаунт.** Проверьте `users:stream` и `users:by-username`: без поиска бот не видит существующий аккаунт.

Токен с правами меняется в боте: **Система → Подключение к панели → API-token**. Адрес и токен проверяются на панели до сохранения, так что неверные права видно сразу.
