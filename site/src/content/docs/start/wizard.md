---
title: Мастер настройки в Telegram
description: "Первичная настройка бота в самом Telegram: язык, база данных, панель, режим установки."
---

После `/start` (или `/setup`, если хотите пройти заново) бот по шагам задаёт вопросы — на каждом вы нажимаете кнопку или присылаете значение. Бот всё проверяет сам.

1. **Язык** — Русский / English.

2. **База данных:**
   - **SQLite** — бот создаёт файл в томе `bot-data`, больше ничего поднимать не нужно. Подходит для небольших магазинов.
   - **PostgreSQL 17** — бот сам допишет сервис `db` в `docker-compose.yml`, поднимет его через `docker.sock` и переключится без перезапуска. Если в SQLite уже были данные — они **переносятся**. Не получилось поднять Postgres — бот спокойно останется на SQLite.

3. **Где бот относительно панели:**
   - **Локально** (рекомендуется) — бот и панель на одном сервере. Бот сам подключится к docker-сети панели; адрес панели подставится как `http://remnawave:3000`.
   - **Удалённо** — панель на другом сервере.

4. **Как установлена панель** (только для «Удалённо»):
   - **Официально (Caddy)**
   - **Скрипт eGames (nginx или Caddy)** — защита по куке в обоих случаях

5. **Реквизиты:**
   - **URL панели** — только для «Удалённо».
   - **API-token панели** — тот, что вы создали в дашборде.
   - **Кука** — только «Удалённо» + eGames. Бот подскажет: на сервере панели в `/opt/remnawave/nginx.conf` есть блок `map $http_cookie $auth_cookie { "~*ИМЯ=ЗНАЧЕНИЕ" 1; }` (в варианте с Caddy — строка `not header Cookie *ИМЯ=ЗНАЧЕНИЕ*` в Caddyfile). Пришлите боту строку `ИМЯ=ЗНАЧЕНИЕ`.
   - **X-API-Key** — если панель закрыта аддоном [«Caddy with security»](https://docs.rw/install/panel-security/). Ключ выпускается в портале аддона (вкладка **API-keys**, обычно `https://ВАШ-ДОМЕН/r/settings/apikeys`). Мастер спросит про него на «Удалённо» + официальной установке; можно задать переменной `CADDY_AUTH_API_TOKEN` в `docker-compose.yml` — тогда ключ применяется при **любом** типе установки и мастер про него не спрашивает.

Ключ и куку можно поменять и после установки, не проходя мастер заново: **Система → 🔐 Доступ к панели**. Там же видно, откуда взят ключ, и есть кнопка проверки связи — бот сразу скажет, подошёл секрет или нет. Пункт показывается только там, где панель чем-то закрыта.

6. **Проверка связи** — бот сам вызывает `/api/system/health` и показывает число пользователей в панели. Если число пришло — связь есть.

Всё введённое хранится в БД зашифрованным и переживает перезапуск — повторно мастер проходить не нужно.
