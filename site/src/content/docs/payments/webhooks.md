ЮKassa, CryptoBot, Platega, Heleket, Tribute и ЮMoney сообщают об оплате **вебхуком** — запросом на ваш сервер. Туда же панель Remnawave шлёт свои события. Бот принимает их на порту **`8080`** внутри контейнера (порт меняется в **Система → 🔗 Вебхуки → 🔌 A: порт бота**).

| Путь | Для чего |
|---|---|
| `/webhook/yookassa` | ЮKassa |
| `/webhook/cryptobot` | CryptoBot |
| `/webhook/platega` | Platega |
| `/webhook/heleket` | Heleket |
| `/webhook/tribute` | Tribute |
| `/webhook/yoomoney` | ЮMoney (уведомления; под `/webhook/yoomoney/…` живут и её страницы оплаты и авторизации) |
| `/webhook/remnawave` | события панели |
| `/healthz` | проверка «жив ли бот» |

## Как вывести бота наружу

В боте это экран **Система → 🔗 Вебхуки**. Выбор зависит от одного: есть ли на сервере бота свой прокси, то есть заняты ли порты 80/443. Стоит бот рядом с панелью или отдельно — неважно.

**A. Прокси есть** — на сервере уже работает веб-сервер, например прокси панели. Встроенный HTTPS не нужен.

1. Дайте прокси дорогу до бота:
   - **прокси в Docker** (например, прокси панели на том же сервере) — адрес бота `remnabot:8080`. К сети панели бот подключается сам, другой прокси подключите к сети бота;
   - **прокси прямо на сервере**, не в Docker, — нажмите **🔌 A: порт бота** и введите порт. Бот откроет его на `127.0.0.1` и перезапустится. Адрес бота — `127.0.0.1:8080`.
2. Добавьте в конфиг прокси блок из раздела [«Настройка прокси»](#nastroyka-proksi) и перезапустите прокси. Готовый блок с адресом вашего бота покажет и кнопка **📋 A: инструкция**.
3. **🔗 A: адрес за прокси** — адрес, на котором прокси принимает запросы, например `https://bot.example.com`.

**B. Прокси нет** — порты 80/443 свободны. Бот сам получит сертификат Let's Encrypt.

1. Направьте домен A-записью на сервер бота (например, `bot.example.com`).
2. **🌐 B: встроенный HTTPS** → **🔗 B: домен** → **🚀 B: применить**. Бот откроет порты 80/443 и перезапустится; сертификат выпустится при первом запросе.

Если порты заняты, бот не применит настройку и предложит вариант A.

## Настройка прокси

Бот работает на одном порту, но на разных путях: вебхуки — `/webhook/`, мини-апп — `/miniapp/`, веб-кабинет — `/cabinet/`, их API — `/api/`, картинки — `/flags/` и `/brand/`.

:::caution[Только /webhook/ мало]
Если пропустить к боту только `/webhook/` (или `/webhook/` и `/cabinet/`), платежи заработают, а мини-апп и кабинет — нет. Кабинет при этом пишет `JSON.parse: unexpected end of data` и не показывает кнопку входа через Telegram.
:::

Проще всего отдать боту весь домен, например `bot.example.com`. Ниже адрес бота `remnabot:8080` — для прокси в Docker. Для прокси прямо на сервере замените его на `127.0.0.1:8080`.

### Caddy

```
bot.example.com {
	reverse_proxy remnabot:8080
}
```

Caddy сам получит сертификат и сам передаст боту `X-Forwarded-Proto` и `X-Forwarded-For`.

### nginx

```nginx
server {
    listen 443 ssl;
    server_name bot.example.com;
    ssl_certificate     /etc/ssl/example.pem;
    ssl_certificate_key /etc/ssl/example.key;

    # Чек об оплате — до 12 МБ; по умолчанию nginx пускает только 1 МБ.
    client_max_body_size 16m;

    location / {
        proxy_pass http://remnabot:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;   # обязательно
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Real-IP $remote_addr;

        # Медленная загрузка чека с телефона не должна обрываться.
        proxy_request_buffering off;
        proxy_read_timeout 120s;
        proxy_send_timeout 120s;
    }
}
```

### Если на домене есть что-то ещё

Тогда пропустите к боту только его пути — все шесть. Если меняли путь кабинета (**Система → 🌐 Веб-кабинет → ✏️ Изменить путь**), впишите свой вместо `cabinet`.

Caddy:

```
bot.example.com {
	@bot path /webhook/* /miniapp/* /api/* /cabinet/* /flags/* /brand/*
	handle @bot {
		reverse_proxy remnabot:8080
	}

	# остальное содержимое домена
}
```

nginx — внутри `server { … }` вашего домена:

```nginx
location ~ ^/(webhook|miniapp|api|cabinet|flags|brand)/ {
    client_max_body_size 16m;
    proxy_pass http://remnabot:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;   # обязательно
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_request_buffering off;
    proxy_read_timeout 120s;
    proxy_send_timeout 120s;
}
```

### Проверка

Включите веб-кабинет и откройте `https://bot.example.com/api/cabinet/config`. Должен прийти короткий ответ вида `{"bot_username":"…","mail_on":false}` — это имя бота и признак настроенной почты, ничего секретного.

- Пустая страница или страница ошибки самого прокси — прокси не пускает к боту `/api/`.
- «требуется HTTPS» — прокси не передаёт `X-Forwarded-Proto: https`.

Для входа в кабинет через Telegram укажите домен кабинета у @BotFather командой `/setdomain`.

:::note[HTTPS обязателен]
Мини-апп, кабинет и их API работают только по HTTPS; исключение — `/webhook/` и `/healthz`. Бот понимает, что HTTPS включён на прокси, по заголовку `X-Forwarded-Proto: https`. Без него API отвечает `426` «требуется HTTPS».

Этому заголовку бот верит только от прокси на той же машине или в той же docker-сети. Если прокси стоит на **другом сервере** с публичным IP, укажите его в [`TRUSTED_PROXIES`](/reference/env/) (`TRUSTED_PROXIES=203.0.113.9`). Иначе кабинет уйдёт в бесконечный редирект на HTTPS, а все посетители попадут под общий лимит запросов и начнут получать `429`.
:::

## Адреса для платёжек

Когда задан домен (вариант B) или адрес за прокси (вариант A), на экране **🔗 Вебхуки** появятся готовые адреса. Их нужно вписать в кабинет провайдера:

- **ЮKassa:** `https://ВАШ_ДОМЕН/webhook/yookassa`
- **CryptoBot:** `https://ВАШ_ДОМЕН/webhook/cryptobot`
- **Platega:** `https://ВАШ_ДОМЕН/webhook/platega`
- **Tribute:** `https://ВАШ_ДОМЕН/webhook/tribute` — подробно в [Tribute](/payments/tribute/)
- **ЮMoney:** `https://ВАШ_ДОМЕН/webhook/yoomoney` — подробно в [ЮMoney](/payments/yoomoney/)
- **Heleket:** вписывать не нужно — бот сам передаёт адрес `https://ВАШ_ДОМЕН/webhook/heleket` в каждом счёте

Вебхуку на слово бот не верит. Оплату ЮKassa и Platega он перепроверяет запросом к провайдеру, у CryptoBot, Heleket и Tribute сверяет подпись, у ЮMoney — и подпись, и операцию в истории кошелька. Поддельный запрос подписку не выдаст.

Если вебхук не дошёл, бот сам периодически перепроверяет неоплаченные счета ЮKassa, CryptoBot, Platega, Heleket и ЮMoney и довыдаёт подписку. Tribute сам повторяет доставку. Но вебхук всё равно стоит настроить: с ним подписка выдаётся сразу.

## Вебхук панели

Нужен для уведомлений пользователям: «подписка скоро истечёт», «подписка истекла», «трафик исчерпан», «доступ приостановлен/восстановлен», а также для [отчётов торрент-блокера](/admin/users/#torrent-bloker).

1. В `.env` панели Remnawave:
   ```
   WEBHOOK_ENABLED=true
   WEBHOOK_URL=https://ВАШ_ДОМЕН/webhook/remnawave
   WEBHOOK_SECRET_HEADER=длинная-случайная-строка
   ```
2. Ту же строку впишите в боте: **Система → 🔗 Вебхуки → 🔑 Секрет панели**. Без секрета отчёты торрент-блокера не принимаются.
3. На панели 2.8.0 и новее для напоминаний об окончании включите ещё `EXPIRATION_NOTIFICATIONS_ENABLED=true`.

## Безопасность на проде

Для продакшена, особенно с мини-аппом и кабинетом, лучше поставить перед ботом свой прокси (Caddy, nginx) или Cloudflare, а не выставлять бота в интернет напрямую. Советы:

- **Wildcard-сертификат** `*.ваш-домен` на прокси. Сертификат на конкретный хост попадает в публичные логи (crt.sh) — по ним кабинет легко найти.
- **Бот без root.** За прокси боту не нужны порты 80/443 — держите его на `127.0.0.1:8080`.
- **Фаервол.** Наружу только 80/443. За Cloudflare пускайте на сервер только его адреса — так реальный IP не виден сканерам.
- **fail2ban / CrowdSec** на прокси против перебора паролей и сканирования. У кабинета есть и свой лимит: 15 попыток входа за 5 минут с одного адреса.
- **Разные домены** для кабинета, панели и страницы подписки.
- **CAA-запись** в DNS, чтобы сертификат на ваш домен мог выпустить только ваш центр сертификации.
