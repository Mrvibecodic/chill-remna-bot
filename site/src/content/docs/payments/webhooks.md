**Вебхук** — запрос, которым платёжная система сообщает боту об оплате. Так работают ЮKassa, CryptoBot, Platega, Heleket, Tribute и ЮMoney. Так же панель Remnawave присылает свои события.

Бот принимает запросы на порту **`8080`** внутри контейнера. Порт меняется в **Система → 🔗 Вебхуки → 🔌 A: порт бота**.

| Путь | Для чего |
|---|---|
| `/webhook/yookassa` | ЮKassa |
| `/webhook/cryptobot` | CryptoBot |
| `/webhook/platega` | Platega |
| `/webhook/heleket` | Heleket |
| `/webhook/tribute` | Tribute |
| `/webhook/yoomoney` | ЮMoney: уведомления. Под `/webhook/yoomoney/…` — её страницы оплаты и авторизации. |
| `/webhook/remnawave` | События панели |
| `/healthz` | Проверка, что бот работает |

## Как вывести бота наружу

Экран **Система → 🔗 Вебхуки**. Вариантов два. Выбор зависит от того, есть ли на сервере бота свой прокси — то есть заняты ли порты 80 и 443. Стоит бот рядом с панелью или отдельно, значения не имеет.

### A. Прокси есть

На сервере уже работает веб-сервер — например, прокси панели. Встроенный HTTPS не нужен.

1. **Путь от прокси до бота:**
   - прокси в Docker (например, прокси панели на том же сервере) — адрес бота `remnabot:8080`. К сети панели бот подключается сам; другой прокси подключается к сети бота;
   - прокси на самом сервере, не в Docker — кнопка **🔌 A: порт бота** и номер порта. Бот открывает порт на `127.0.0.1` и перезапускается. Адрес бота — `127.0.0.1:8080`.
2. **Блок в конфиге прокси** — добавить блок из раздела [Настройка прокси](#nastroyka-proksi) и перезапустить прокси. Готовый блок с адресом бота показывает кнопка **📋 A: инструкция**.
3. **🔗 A: адрес за прокси** — адрес, на котором прокси принимает запросы, например `https://bot.example.com`.

### B. Прокси нет

Порты 80 и 443 свободны. Бот сам получает сертификат Let's Encrypt.

1. Направить домен (например, `bot.example.com`) A-записью на сервер бота.
2. **🌐 B: встроенный HTTPS** → **🔗 B: домен** → **🚀 B: применить**. Бот открывает порты 80 и 443 и перезапускается. Сертификат выпускается при первом запросе.

Если порты заняты, бот не применяет настройку и предлагает вариант A.

## Настройка прокси

Бот работает на одном порту, но на разных путях:

| Путь | Что там |
|---|---|
| `/webhook/` | вебхуки |
| `/miniapp/` | мини-апп |
| `/cabinet/` | веб-кабинет |
| `/api/` | API мини-аппа и кабинета |
| `/flags/`, `/brand/` | картинки |

:::caution[Только /webhook/ недостаточно]
Если к боту пропущен только `/webhook/` (или `/webhook/` и `/cabinet/`), платежи работают, а мини-апп и кабинет — нет. Кабинет при этом пишет `JSON.parse: unexpected end of data` и не показывает кнопку входа через Telegram.
:::

В примерах боту отдан весь домен `bot.example.com`. Адрес бота `remnabot:8080` — для прокси в Docker. Для прокси на самом сервере вместо него нужен `127.0.0.1:8080`.

### Caddy

```
bot.example.com {
	reverse_proxy remnabot:8080
}
```

Caddy сам получает сертификат и передаёт боту `X-Forwarded-Proto` и `X-Forwarded-For`.

### nginx

```nginx
server {
    listen 443 ssl;
    server_name bot.example.com;
    ssl_certificate     /etc/ssl/example.pem;
    ssl_certificate_key /etc/ssl/example.key;

    # Чек об оплате — до 12 МБ; по умолчанию nginx пускает только 1 МБ.
    client_max_body_size 16m;

    location / {
        proxy_pass http://remnabot:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;   # обязательно
        proxy_set_header X-Forwarded-For $remote_addr;
        proxy_set_header X-Real-IP $remote_addr;

        # Медленная загрузка чека с телефона не должна обрываться.
        proxy_request_buffering off;
        proxy_read_timeout 120s;
        proxy_send_timeout 120s;
    }
}
```

### Если на домене есть что-то ещё

К боту нужно пропустить только его пути — все шесть. Если путь кабинета изменён (**Система → 🌐 Веб-кабинет → ✏️ Изменить путь**), вместо `cabinet` указывается он.

Caddy:

```
bot.example.com {
	@bot path /webhook/* /miniapp/* /api/* /cabinet/* /flags/* /brand/*
	handle @bot {
		reverse_proxy remnabot:8080
	}

	# остальное содержимое домена
}
```

nginx — внутри `server { … }` домена:

```nginx
location ~ ^/(webhook|miniapp|api|cabinet|flags|brand)/ {
    client_max_body_size 16m;
    proxy_pass http://remnabot:8080;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;   # обязательно
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_request_buffering off;
    proxy_read_timeout 120s;
    proxy_send_timeout 120s;
}
```

### Проверка

При включённом веб-кабинете адрес `https://bot.example.com/api/cabinet/config` отдаёт короткий ответ вида `{"bot_username":"…","mail_on":false}` — имя бота и признак настроенной почты.

| Что пришло | Причина |
|---|---|
| Пустая страница или страница ошибки прокси | Прокси не пропускает к боту `/api/`. |
| «требуется HTTPS» | Прокси не передаёт `X-Forwarded-Proto: https`. |

**Вход в кабинет через Telegram.** Домен кабинета нужно указать у @BotFather командой `/setdomain`.

**Новый Login Widget.** Если в @BotFather у бота включён новый Login Widget, прежняя кнопка входа показывает страницу «deprecated». Виджет настраивается по [инструкции Telegram](https://core.telegram.org/bots/telegram-login#registering-your-allowed-urls):

- **Redirect URIs** — адрес кабинета точно как в браузере, например `https://bot.example.com/cabinet/`;
- **Trusted Origins** — `https://bot.example.com`;
- Client ID совпадает с числом до двоеточия в токене бота.

После этого в настройках веб-кабинета в боте нужно переключить **🔑 Вход через Telegram** на «новый».

:::note[HTTPS обязателен]
Мини-апп, кабинет и их API работают только по HTTPS. Исключение — `/webhook/` и `/healthz`. О том, что HTTPS включён на прокси, бот узнаёт по заголовку `X-Forwarded-Proto: https`. Без него API отвечает `426` «требуется HTTPS».

Этому заголовку бот верит только от прокси на той же машине или в той же docker-сети. Прокси на **другом сервере** с публичным IP нужно указать в [`TRUSTED_PROXIES`](/reference/env/), например `TRUSTED_PROXIES=203.0.113.9`. Иначе кабинет уходит в бесконечный редирект на HTTPS, а все посетители попадают под общий лимит запросов и получают `429`.
:::

## Адреса для платёжек

Когда задан домен (вариант B) или адрес за прокси (вариант A), на экране **🔗 Вебхуки** появляются готовые адреса. Их нужно вписать в кабинете платёжной системы.

| Система | Адрес |
|---|---|
| ЮKassa | `https://ВАШ_ДОМЕН/webhook/yookassa` |
| CryptoBot | `https://ВАШ_ДОМЕН/webhook/cryptobot` |
| Platega | `https://ВАШ_ДОМЕН/webhook/platega` |
| Tribute | `https://ВАШ_ДОМЕН/webhook/tribute` — [Tribute](/payments/tribute/) |
| ЮMoney | `https://ВАШ_ДОМЕН/webhook/yoomoney` — [ЮMoney](/payments/yoomoney/) |
| Heleket | Вписывать не нужно: бот сам передаёт адрес `https://ВАШ_ДОМЕН/webhook/heleket` в каждом счёте. |

**Проверка запросов.** Поддельный запрос подписку не выдаёт:

- ЮKassa и Platega — бот перепроверяет оплату запросом к платёжной системе;
- CryptoBot, Heleket и Tribute — бот сверяет подпись;
- ЮMoney — бот сверяет подпись и операцию в истории кошелька.

**Если вебхук не дошёл.** Бот сам периодически перепроверяет неоплаченные счета ЮKassa, CryptoBot, Platega, Heleket и ЮMoney и выдаёт подписку. Tribute повторяет доставку сам. С настроенным вебхуком подписка выдаётся сразу, без ожидания перепроверки.

## Вебхук панели

Нужен для уведомлений пользователям — «подписка скоро истечёт», «подписка истекла», «израсходовано N% трафика», «трафик исчерпан», «доступ приостановлен / восстановлен» — и для [отчётов торрент-блокера](/admin/users/#torrent-bloker).

1. В `.env` панели Remnawave:
   ```
   WEBHOOK_ENABLED=true
   WEBHOOK_URL=https://ВАШ_ДОМЕН/webhook/remnawave
   WEBHOOK_SECRET_HEADER=длинная-случайная-строка
   ```
2. Та же строка — в боте: **Система → 🔗 Вебхуки → 🔑 Секрет панели**. Без секрета бот события панели не принимает. Когда такое событие приходит впервые после запуска, бот пишет об этом администратору.
3. На панели 2.8.0 и новее для напоминаний об окончании подписки — ещё `EXPIRATION_NOTIFICATIONS_ENABLED=true` и список сроков в часах, например `EXPIRATION_NOTIFICATIONS=[-72, -48, -24, 24]`: минус — до окончания, плюс — после. Без списка панель не запускается. Предупреждение за то же число дней, за которое напоминает сам бот ([🔔 Уведомления](/admin/marketing/)), не дублируется.
4. Для предупреждения о расходе трафика — `BANDWIDTH_USAGE_NOTIFICATIONS_ENABLED=true` и пороги в процентах, например `BANDWIDTH_USAGE_NOTIFICATIONS_THRESHOLD=[60, 80]`.

**Бот и прослойка подписок.** Если события панели нужны ещё и [прослойке подписок](https://github.com/Mrvibecodic/remnawave-subscription-middleware), оба адреса нужно вписать через запятую:

```
WEBHOOK_URL=https://ВАШ_ДОМЕН/webhook/remnawave,https://ДОМЕН_ПРОСЛОЙКИ/webhook.php
```

Секрет у панели один на все адреса, поэтому в боте и в прослойке он одинаковый.

| Что видно | Причина |
|---|---|
| Не приходит ничего | В боте не задан секрет панели, секрет в боте и в `.env` панели разный, адрес бота в `WEBHOOK_URL` неверный или не включён `WEBHOOK_ENABLED`. |

## Безопасность на проде

Меры защиты для бота с мини-аппом и кабинетом, открытого в интернет:

| Мера | Зачем |
|---|---|
| Свой прокси (Caddy, nginx) или Cloudflare перед ботом | Бот не выставлен в интернет напрямую. |
| Wildcard-сертификат `*.ваш-домен` на прокси | Сертификат на конкретный хост попадает в публичные логи (crt.sh), по ним кабинет находится. |
| Бот на `127.0.0.1:8080` | За прокси боту не нужны порты 80 и 443 и права root. |
| Фаервол: наружу только 80 и 443 | За Cloudflare на сервер пускаются только его адреса — реальный IP не виден сканерам. |
| fail2ban или CrowdSec на прокси | Защита от перебора паролей и сканирования. У кабинета есть свой лимит: 15 попыток входа за 5 минут с одного адреса. |
| Разные домены для кабинета, панели и страницы подписки | Одно не находится по другому. |
| CAA-запись в DNS | Сертификат на домен выпускает только указанный центр сертификации. |
