[Tribute](https://tribute.tg) продаёт доступ **подпиской на Telegram-канал**. Покупатель оформляет подписку на странице Tribute, Tribute списывает деньги (и дальше продлевает её сам), а боту присылает вебхук. Бот по вебхуку выдаёт подписку в панели Remnawave.

## Как это устроено

1. В Tribute у вас есть **подписка** с одним или несколькими **периодами** (неделя, месяц, 3 месяца, полгода, год), у каждого своя цена.
2. Каждый тариф бота привязан к **своей** подписке Tribute. У «Базового» — ссылка оплаты и (по желанию) ID подписки, у остальных тарифов — ID подписки и ссылка обязательно.
3. Покупатель в боте выбирает тариф → «🎁 Оплатить через Tribute» → открывается страница подписки Tribute → он выбирает период и платит.
4. Tribute присылает `new_subscription`, а при каждом автопродлении — `renewed_subscription`. Бот находит **тариф по ID подписки** (`subscription_id`), **срок — по периоду** (`period`) и выдаёт подписку по условиям тарифа.

Цена, которую покупатель видит в боте, — цена бота; платит он цену Tribute. **Цены не сверяются** — держите их одинаковыми сами.

## Настройка в Tribute

1. **Канал.** Создайте приватный канал (можно пустой) и подключите его в Tribute — без канала подписку не создать. Tribute попросит добавить своего бота в канал администратором.
2. **Подписка.** Дэшборд автора → **Подписки** → канал → **Подписка**: название, описание, текст кнопки → **Продолжить** → периоды, цены и валюта (₽, $ или €) → **Создать** ([инструкция Tribute](https://wiki.tribute.tg/ru/for-content-creators/subscriptions/creating-subscription)).
   Каждому тарифу бота нужна своя подписка. Периоды подписки должны совпадать со сроками тарифа — см. [таблицу](#периоды-и-сроки).
3. **Ссылка.** У подписки откройте **Ссылки** и скопируйте **Telegram-ссылку** (`t.me/tribute/app?startapp=…`), а не веб-ссылку (`web.tribute.tg/s/…`): при оплате через веб покупатель может войти по почте, и тогда Tribute не передаёт его Telegram ID — выдать подписку некому ([про ссылки](https://wiki.tribute.tg/ru/for-content-creators/subscriptions/subscription-publishing)).
4. **API-ключ и вебхук.** Дэшборд автора → **Настройки** (меню «⋯») → **API-ключи**: создайте ключ и укажите URL вебхука `https://ВАШ_ДОМЕН/webhook/tribute`. Один ключ служит и для подписи вебхуков, и для списка подписок. Домен и проксирование — [Вебхуки и reverse-proxy](/payments/webhooks/).

## Настройка в боте

**Продажи → 🎁 Tribute:**

- **тумблер** — показывать ли Tribute покупателям. Оплаты, пришедшие при выключенном тумблере, всё равно выдаются (деньги уже приняты), в журнал пишется предупреждение;
- **🔑 API-ключ** — тот, что создан в Tribute. Без него вебхук отвергается (Tribute будет повторять доставку сутки, так что оплата не потеряется, если вписать ключ вовремя);
- **🔗 Ссылка «Базового»** — Telegram-ссылка на подписку «Базового».

**🎁 Tribute → 🧾 Тарифы и подписки** — список всех тарифов:

| Метка | Значение |
|---|---|
| ✅ | у тарифа есть кнопка Tribute |
| ⚠️ | привязка неполная (нет подписки или ссылки) |
| ➖ | не привязан |
| ♻️ | прежняя подписка тарифа — кнопки нет, продления её подписчиков выдают этот тариф |
| ♻️ … ❌ | подписка удалённого тарифа — оплаты по ней отклоняются |

В карточке тарифа:

- **📋 Выбрать из Tribute** — бот запрашивает ваши подписки по API и показывает их с периодами; 🔒 — подписка уже закреплена за другим тарифом. После выбора в карточке видно, какие периоды подписки покрыты сроками тарифа и какие будут отклоняться;
- **🔢 Ввести ID** — если API недоступен. ID подписки есть в журнале платежей: строка `webhook` содержит «подписка #ID «название»»;
- **🔗 Ссылка оплаты** — Telegram-ссылка на эту подписку;
- **🗑 Отвязать подписку** — см. [перепривязку](#перепривязка-отвязка-удаление).

Кнопка «Оплатить через Tribute» появляется у тарифа, только когда заданы **и подписка, и ссылка**, а у «Базового» — ссылка.

## Периоды и сроки

| Период Tribute | Что выдаёт бот | Какой срок тарифа нужен |
|---|---|---|
| `weekly` | 7 дней | 1 месяц (условия берутся от него) |
| `monthly` | 1 месяц | 1 месяц |
| `quarterly` | 3 месяца | 3 месяца |
| `halfyearly` | 6 месяцев | 6 месяцев |
| `yearly` | 12 месяцев | 12 месяцев |
| `onetime`, `trial` | не выдаётся | — |

«Нужен срок» — у тарифа должен быть этот срок **с ценой**: из него берутся трафик, лимит устройств и сквады. Если срока нет, оплата по такому периоду не выдаётся, а вам и покупателю приходит уведомление. Поэтому **периоды подписки в Tribute заводите только те, что есть в тарифе** — карточка тарифа в боте подсветит лишние.

Бесплатные события Tribute (пробный период, подарок, нулевая сумма) подписку не выдают: у бота свой триал.

## Что видит покупатель

- В чате, мини-аппе и веб-кабинете — кнопку «🎁 Оплатить через Tribute» на экране способов оплаты. Рядом бот перечисляет сроки, которые выдаёт по этой подписке; если ни один период подписки не покрыт тарифом, кнопки нет.
- Аккаунтам веб-кабинета, вошедшим по e-mail без привязки Telegram, Tribute не показывается: Tribute выдаёт доступ по Telegram ID покупателя.
- Платить нужно **тем же Telegram-аккаунтом**, что в боте: подписка выдаётся на `telegram_user_id` из Tribute.
- После оплаты бот сам присылает сообщение «подписка активна» со ссылкой.

## Продления, отмена, автосписание

- **Продление.** Tribute продлевает подписку сам и присылает `renewed_subscription` — бот продлевает срок по текущим условиям тарифа.
- **Отмена.** Отмена в Tribute выключает автопродление: оплаченный срок дорабатывает, бот доступ **не отбирает** (событие `cancelled_subscription` пишется в журнал).
- **Автосписание картой.** Если у покупателя было включено автопродление картой (ЮKassa), после оплаты через Tribute бот его **выключает** и сообщает об этом — иначе за один срок списывалось бы дважды. Включить обратно можно в разделе автопродления.
- **Трафик при недельной оплате.** Лимит трафика у недели — месячного срока тарифа. Продление того же тарифа неделей трафик не обнуляет (его сбрасывает стратегия сброса тарифа), а первая покупка, смена тарифа, оплата после истечения подписки и стратегия «без сброса» — обнуляют.
- **Смена тарифа.** Покупка через Tribute другого тарифа пересчитывает остаток текущей подписки так же, как у остальных способов оплаты (зачёт по соотношению цен).

## Перепривязка, отвязка, удаление

- **Привязать к тарифу другую подписку** или нажать **🗑 Отвязать подписку** — прежняя подписка остаётся за тарифом (♻️): кнопки у неё нет, но её подписчики продолжают платить Tribute и получать этот тариф. Ссылка оплаты тарифа (и ссылка «Базового») после смены подписки сбрасывается — задайте её заново.
- **Удалить тариф** — его подписка остаётся в списке с ❌: оплаты по ней отклоняются с уведомлением (выдать удалённый тариф нельзя). Отмените такие подписки в Tribute или привяжите подписку к другому тарифу.
- **♻️ Забыть подписку** (с подтверждением) — убирает её из привязок совсем: дальше она ведёт себя как непривязанная (см. ниже). Подписка, закреплённая за тарифом, к другому тарифу не привязывается, пока её не забыть; текущую сначала отвяжите.

## Подписки без привязки и чужие каналы

По умолчанию подписка Tribute, не привязанная ни к одному тарифу, выдаёт **«Базовый» по периоду** — так Tribute работал до привязки тарифов.

Вебхук Tribute приходит на **весь аккаунт автора**. Если у вас в Tribute есть другие платные каналы, их подписчики тоже получили бы «Базовый». Чтобы этого не было, задайте **ID подписки и у «Базового»**: тогда подписки без привязки ничего не выдают, а вам приходит уведомление. Ссылка «Базового» в этом случае должна вести именно на эту подписку. «Отвязать» у «Базового» возвращает прежний режим.

## Отказы и уведомления

| Ситуация | Что делает бот |
|---|---|
| Подпись вебхука не сошлась / не задан API-ключ | отвечает 401, Tribute повторяет доставку около суток; в журнале `sign_error` |
| Повторная доставка уже выданной оплаты | пропускает (`duplicate`) |
| Пробный период, подарок, нулевая сумма | не выдаёт (`not_a_payment`) |
| Неизвестный период (`onetime`, `trial`, новый) | не выдаёт, уведомляет вас и покупателя |
| В тарифе нет нужного срока | не выдаёт, уведомляет вас и покупателя |
| Подписка удалённого тарифа | не выдаёт, уведомляет вас и покупателя |
| Непривязанная подписка при заданном ID «Базового» | не выдаёт, уведомляет вас и покупателя |
| Нет Telegram ID (покупатель вошёл в Tribute по почте) | не выдаёт, уведомляет вас — найдите покупателя в кабинете Tribute и выдайте доступ вручную |
| Тариф выключен или недоступен покупателю по режиму доступности | **выдаёт** (деньги приняты) и уведомляет вас |
| Панель или база недоступны | отвечает ошибкой, Tribute повторяет доставку |

Каждый шаг пишется в журнал платежей: **История платежей → 🧾 Лог заказа**, поиск по Telegram ID покупателя. Строка `webhook` содержит тип события, период, сумму, `trb=T-…`/`W-…` (ID покупателя в Tribute), `@username` и подписку.

## Нюансы

- **Ссылка статична** и работает и вне бота: режим доступности тарифа («только новым», «по списку» и т. п.) её не закрывает. Если тариф оплатил тот, кому он недоступен, подписка выдаётся, а вам приходит уведомление.
- **Изменение цены в Tribute** действует только для новых подписчиков: старые продлеваются по старой цене, а бот выдаёт текущие условия тарифа.
- **Лимиты Tribute:** минимальная транзакция — 100 ₽ / 1 $ / 1 €, комиссия — около 10% ([комиссии и лимиты](https://wiki.tribute.tg/ru/for-content-creators/fees-limits-currencies)). Недельная цена не может быть ниже минимума.
- **Суммы в журнале** — то, что заплатил покупатель (до комиссии Tribute). Платежи в $ и € в рублёвую выручку статистики и в процент рефереру не идут — бот не конвертирует валюты.
- **Чеки «Мой налог»** по Tribute не формируются — только по ЮKassa.
- **Откат версии бота.** Предыдущие версии про привязки не знают: при первом же сохранении настроек они сотрутся, и все подписки Tribute снова будут выдавать «Базовый» по периоду.

## Проверка

1. Укажите вебхук и ключ, в боте включите Tribute.
2. Если в кабинете Tribute есть отправка тестового события — в журнале платежей появится «тестовый вебхук принят, подпись верна». Строка `sign_error` — ключ в боте не тот.
3. Оформите подписку сами (с того же Telegram, что в боте) и проверьте, что пришло «подписка активна» и в панели нужный тариф и срок.
